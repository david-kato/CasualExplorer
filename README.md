# CasualExplorer（CE）

Windowsでファイルやフォルダを視覚的に探すための、読取り専用v0.1試作です。通常の一覧と、カードを画面上だけで動かせる「重力プレビュー」を切り替えられます。Windows標準エクスプローラーを置き換えるものではありません。

## 1. できること・できないこと

- 起動時は同梱ダミーファイル35件のうち、新しい順で30件を表示します。
- 「ローカルフォルダを選ぶ」で、ユーザが明示選択したローカル1フォルダの直下だけを表示できます。
- 名前・種類・更新日時という「ファイルの基本情報」だけを読みます。選択先では普通のフォルダも表示しますが、開いたり下の階層へ進んだりしません。
- 更新日時の降順、同日時は名前順で最大30項目。同じ読取り結果を一覧と重力プレビューで共有します。
- 選択の取消し、読取りの中止、同梱ダミーへの復帰ができます。
- ファイルの内容表示、ファイルを開く操作、階層移動、31項目目以降の追加表示、検索・並び替えの切替は未実装です。

## 2. 必要な環境と導入の条件

確認済みの開発対象はWindows上のx64、Debug・win-x64です。別OS、ARM64/x86、別環境での再現を確認済みとは扱いません。プロジェクトの最小Windows指定は10.0.17763.0ですが、その全バージョンでの動作保証ではありません。

ビルド（ソースから実行用一式を作ること）には、次の既存環境を使います。

- .NET SDK 10.0.400 x64：プロジェクト内 .tools/dotnet。
- NuGetキャッシュ（依存部品の保存場所）：.tools/nuget-packages。
- 復元済みの依存情報：src/CasualExplorer.App/obj/project.assets.json。
- 固定依存：Microsoft.WindowsAppSDK 1.8.260317003、Microsoft.Windows.SDK.BuildTools 10.0.26100.7705、Microsoft.Windows.SDK.BuildTools.WinApp 0.3.1。
- コマンドラインでの確認済みビルド手順は、既存Visual Studioの変更を必要としません。Visual StudioのWinUI application developmentワークロードはIDE利用側の条件と区別します。

SDKやキャッシュがないPCでは、ここで止めます。実在・版・不足を確認し、取得が必要なら内容・理由・版・容量・保存先を示してあなたの承認を得てから復元します。この説明書の存在は取得・インストールの承認ではありません。SDK、キャッシュ、bin、objをGitや別PCの生成物から流用しません。Visual Studioの修復・更新・構成変更、Windows設定変更は行いません。

公開ソースにはobjや依存部品を含めません。そのため新しい環境では、SDK準備とNuGet復元（固定版の依存部品を揃えること）を承認のうえ行ってからビルドします。下の環境変数を先に設定し、ネットワーク取得を承認済みの場合だけ次を実行してください。依存版は更新しません。

~~~powershell
& './.tools/dotnet/dotnet.exe' restore './src/CasualExplorer.App/CasualExplorer.App.csproj' --runtime win-x64 --source 'https://api.nuget.org/v3/index.json'
~~~

この復元はbin/obj/.tools内を更新し、部品や監査情報のネットワーク取得を伴う場合があります。承認・必要環境がない場合は実行せず、依存取得を回避するために別PCの生成物をコピーして補わないでください。新しい環境でのREADMEのみの再現試験は未実施です。

すでに実行用一式がある場合は「4. 起動」へ進めます。自己完結型（必要な.NET/Windows App SDKランタイムを一式に含む方式）なので、起動のためのSDK導入や環境変数指定は不要です。

## 3. 既存環境でビルドする

この操作はプロジェクト内のbin/objなどのビルド生成物を更新します。個人ファイルを変更する操作ではありませんが、生成物を変えたくない場合は実行せず、既存の本体を起動してください。

1. Windows標準エクスプローラーで、README.mdとsrcが入ったCasualExplorerフォルダを開きます。
2. 空いている場所の右クリックから「ターミナルで開く」でPowerShellを開きます。管理者実行は不要です。
3. 次の確認を実行します。Falseがあればビルドせず、「2. 必要な環境と導入の条件」へ戻ります。

   ~~~powershell
   Test-Path -LiteralPath './.tools/dotnet/dotnet.exe'
   Test-Path -LiteralPath './.tools/dotnet/sdk/10.0.400'
   Test-Path -LiteralPath './.tools/nuget-packages'
   Test-Path -LiteralPath './src/CasualExplorer.App/obj/project.assets.json'
   ~~~

4. 既存環境で次を実行します。このPowerShell内だけの指定であり、Windowsの永続設定を変更しません。証明書の自動生成と初回処理を避け、依存部品を自動取得せずビルドします。

   ~~~powershell
   $ceRoot = (Resolve-Path -LiteralPath '.').Path
   $env:DOTNET_CLI_HOME = Join-Path $ceRoot '.tools/dotnet-home'
   $env:NUGET_PACKAGES = Join-Path $ceRoot '.tools/nuget-packages'
   $env:DOTNET_ROOT = Join-Path $ceRoot '.tools/dotnet'
   $env:DOTNET_ROOT_X64 = $env:DOTNET_ROOT
   $env:DOTNET_CLI_TELEMETRY_OPTOUT = '1'
   $env:DOTNET_SKIP_FIRST_TIME_EXPERIENCE = '1'
   $env:DOTNET_GENERATE_ASPNET_CERTIFICATE = 'false'
   & './.tools/dotnet/dotnet.exe' build './src/CasualExplorer.App/CasualExplorer.App.csproj' --configuration Debug --property:Platform=x64 --runtime win-x64 --no-restore
   ~~~

5. 最後に「ビルドに成功しました」「0 個の警告」「0 エラー」が出れば成功です。--no-restoreは依存部品の再取得をしない指定です。依存不足で失敗したら、この指定を外したりパッケージを更新したりせず、エラーを保存して復元の承認条件を確認してください。
6. 実行用一式は ビルド出力フォルダ（src/CasualExplorer.App/bin/x64/Debug/net10.0-windows10.0.26100.0/win-x64） にできます。EXEだけを取り出して実行しないでください。

## 4. 起動して成功を確認する

1. 上のビルド出力フォルダをWindows標準エクスプローラーで開きます。
2. CasualExplorer.exeをダブルクリックして通常起動します。管理者実行はしません。
3. ウィンドウ名「CasualExplorer v0.1」、青い「読取り専用」、「安全モード」を確認します。
4. 対象が「同梱ダミーフォルダ: Samples\TestData」であること、一覧に「ファイル名」「種類」「更新日時」の3列があることを確認します。
5. 下部の状態欄に「30件を表示」「通常ファイル全35件」「リンク0件をスキップ」「ファイル変更は行いません」が出れば、通常の同梱表示です。狭い画面ではページ全体を縦スクロールして状態欄を見てください。
6. 終了は右上の「閉じる」です。再起動時は同梱ダミーから始まり、選んだフォルダは保存しません。

保存状態によっては「同梱ダミーフォルダまたはファイルが見つかりません」と表示されます。保管・復元途中の状態としてあり得ますが、同梱成功の確認にはなりません。アプリ一式の再ビルドを案内どおり行い、個人ファイルや別フォルダをコピーして穴埋めしないでください。

## 5. 重力プレビューを使う

1. 「重力プレビュー」を押します。同じ最大30項目がカードになります。
2. 初回と「配置を戻す」は共通の約0.8秒の滑らかな動きです。カードは種類ごとの枠へまとまります。
3. カードをクリックすると、選択枠とチェック印が付き、下部で名前・種類・更新日時を確認できます。名前が省略されていても詳細欄で確認できます。
4. カードをドラッグすると画面上の位置だけが変わります。離すと再配置し、「配置が安定しました」の時点では重なりを解消します。
5. 「一時停止」中は自動配置を止めるので、カードをずらして重ねたままにもできます。「再開」後に重なりを解消します。「配置を戻す」は停止中でも初期表示位置へ戻し、停止状態は維持します。
6. 「一覧」で元の3列へ戻ります。Tab／Shift+Tabで主要ボタンへ移動し、Space／Enterでも操作できます。

ドラッグはファイルの移動ではありません。厳密な物理シミュレーション、自由配置の保存、本格的なファイルマップではなく、表示専用の試作です。

## 6. ローカルフォルダを選ぶ・取り消す

最初の動作確認には個人・共有データではなく、プロジェクト内の同梱ダミーを使ってください。

1. 「ローカルフォルダを選ぶ」を押します。
2. Windowsの選択画面でアドレス欄を選び（Alt+D）、このプロジェクトのsamples/TestDataフォルダの実際の場所を入力してEnterを押します。フォルダ選択画面なので、ファイルが一覧に出なくても正常です。
3. 「このフォルダを表示」で確定します。対象に選択した経路と「直下のみ」、一覧に最大30項目、状態欄に直下の通常項目数・リンク/未対応のスキップ数が表示されます。同梱データを選べば35項目中30項目が目安です。
4. 選択画面の「キャンセル」は元の対象・表示を保ちます。読み始めた後にやめる場合は、アプリの「読取りを中止」を押します。中止でも元の表示を保ちます。
5. 「同梱ダミーに戻す」で実行フォルダ内の固定同梱先へ戻れます。

選択先の読取りに失敗すると一覧を空にして理由を表示します。別フォルダへ自動的に切り替えません。一方、選択画面自体を開けない場合は元の表示を維持します。

## 7. 安全制限

- 読むのは基本情報だけ。再帰（下の階層までたどること）、内容読取り、実ファイルを開く操作はありません。
- 移動、コピー、名前変更、削除、上書き、暗号化、AI整理、外部ドロップ、他アプリ起動はありません。
- 選んだ経路・カード座標の保存、アプリからの外部送信はありません。選択経路は画面内には表示されます。
- 選択対象はWindowsが固定/リムーバブルと判定するローカルドライブだけ。ネットワーク共有（UNC）、ネットワークドライブ、デバイス形式の経路は対象外です。
- リンク属性（再解析ポイント）のある祖先/選択フォルダは拒否し、直下のリンクはスキップします。リンク先を調べるためにたどりません。普通の.lnk/.urlファイルは基本情報だけ表示する場合がありますが、その内容やリンク先は開きません。
- オフライン・クラウドの未取得データを示す属性は拒否/スキップします。すべてのクラウド製品の実動作を検証したという意味ではありません。
- 読取り中の経路差替えを避けるため祖先から読取りハンドルを保持します。安全を確定できない場所は拒否し、使用中のフォルダでも拒否する場合があります。権限を緩めたり、管理者実行で回避したりしません。
- 選択先では最大10000項目または約2500msを項目間で検査して走査を打ち切ります。打切り時は「確認済み」と「総数と全体の最新順は未確定」を表示します。上位30項目も確認できた範囲内のものです。経路の深さは64までです。
- この時間制限はOSへの問合せ1回を厳密に中断する保証ではありません。読取りは画面操作と別の処理で行い、中止・終了を受け付けます。
- 同梱先の安全境界は実行フォルダ内のSamples/TestDataに固定です。選択先は明示選択した1フォルダに限定し、両者を混同しません。
- Windows標準の選択画面自身の一覧、最近の場所、履歴、既存クラウドプロバイダの通信等はOS側の挙動です。アプリの制限を、その画面まで含めた履歴/通信ゼロの保証とは扱いません。

## 8. うまくいかないとき・既知問題

| 表示や症状 | 意味と対応 |
|---|---|
| スクロールしても30項目まで | 現仕様です。続き表示は未実装（計画17）。総数と表示件数は別です。 |
| 読取りが0項目 | 空フォルダ、リンク等のみ、または失敗の可能性があります。スキップ数と理由を確認してください。 |
| 「安全に読取りできません」 | リンク/ネットワーク/オフライン/権限不足/使用中など。権限や設定を変えず、通常のローカルダミーで確認するか「同梱ダミーに戻す」を使います。 |
| 「総数と全体の最新順は未確定」 | 選択先の走査制限です。フォルダ全体を確認し終わったとは判断しません。 |
| 同梱先が見つからない | 一式の不足です。再ビルドし、別の実ファイルで補いません。 |
| 起動しない/依存不足 | EXE単体でなく一式と同梱先を確認。エラーを記録し、勝手にインストールやVS修復をしません。 |
| 停止中はカードが重なる | 停止中の手動操作は保持します。「再開」後の安定配置でも重なる場合は不具合として報告してください。 |
| 狭い画面で操作や詳細が見えない | ページ全体と重力領域をスクロールし、必要なら「一覧」に戻ります。 |

- 自己完結型のDebug出力は多数のファイルを含みます。過去の513ファイル/215.1MiBは2026-09-21時点の値で、現版の容量ではありません。固定容量や単一EXE配布とは説明しません。
- 同梱ダミーの更新日時は取得/展開方法で変わる場合があります。READMEにある特定のファイル名順ではなく、実際の日時順で確認してください。
- 同梱ダミー35件は一覧試験用の短い説明テキストです。拡張子がPNG/PDF/DOCXなどでもその形式の実データではなく、開いて使うための見本ではありません。CEは内容を開きません。
- 実DPI150%（画面の拡大率）でのサイズ試験は合格済みですが、別モニター間のDPI切替は機器なしで未確認です。クラウドプロバイダ実体やオフライン媒体の全動作も未確認です。
- 7Cのビルド・安全/例外/実リンク/実拒否・24追加条件・全UI/負荷/3分操作は各2回合格した過去の記録です。今回の文書更新で新たにGUI試験をしたものではありません。失敗・再試験も開発側の非公開試験記録に残しています。
- 更新版のv0.1採用とREADMEはあなたが確認済みです。公開前点検、公開、別環境でREADMEだけを使う再現確認は残っています。

## 9. ファイルを変更しない安全点検

これはビルドやGUI動作試験の代わりではなく、ソースの安全条件と同梱ハッシュの点検です。上のビルド操作とは異なり、ファイルを変更しません。

1. CasualExplorerで開いたPowerShellから次を実行します。スクリプト実行が端末の方針で拒否されたら止め、実行ポリシーの永続変更や管理者実行はしません。

   ~~~powershell
   & './tests/Verify-ReadOnlyV01.ps1'
   & './tests/Verify-Step4SafetyBoundary.ps1' -OutputRoot './src/CasualExplorer.App/bin/x64/Debug/net10.0-windows10.0.26100.0/win-x64'
   & './tests/Verify-Step7CSafety.ps1'
   ~~~

2. 順に「CasualExplorer v0.1 骨格確認: 成功」「CasualExplorer step 4 safety boundary: PASSED」、最後のJSONのResultがPASSなら成功です。どれかが失敗したら、最後の成功だけで全体合格とは扱いません。
3. 実リンク/権限/大量件数の開発試験は専用領域と別の実行条件が必要です。通常操作として実行せず、開発担当へ確認してください。公開候補には実リンク/権限試験の前提ダミーや記録を含めていません。
